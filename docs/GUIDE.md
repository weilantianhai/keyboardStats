## 快速上手

1. 从 [Releases](https://github.com/weilantianhai/keyboardStats/releases) 下载 `KeyboardStats-v1.0.zip`，解压到任意目录。
2. 运行 `KeyboardStats.exe`，主窗口打开，同时系统托盘出现键盘图标（后台记录进程）。
3. 第一次启动会询问是否开启**开机自启动**——开启后每次开机自动在后台记录，无需手动打开程序。
4. 正常使用电脑即可，程序在后台统计所有键盘按键与鼠标点击；接上手柄（XInput 模式）后，
   手柄按键同样会被统计。
5. 随时通过托盘图标（右键 → 「打开 KeyboardStats」）或主窗口查看统计。

> 程序只记录**按键次数与时间戳**，不记录按键内容、不联网，数据全部保存在本地。

## 主界面：看板与热力图

主界面从上到下分为四块：

### 统计看板（顶部横条）

| 卡片 | 含义 |
|---|---|
| 活跃分数 | 综合活跃度，权重见下 |
| 今日键盘 | 今天敲击键盘的次数（不含鼠标/手柄） |
| 今日鼠标 | 今天点击鼠标的次数（不含滚轮） |
| 今日手柄 | 今天按下手柄按键的次数（不含摇杆行程与扳机） |
| 滚轮格数 | 今天滚动滚轮的格数 |
| 使用天数 | 从第一条记录到今天的自然天数 |
| 活跃天数 | 实际有记录的天数 |

**活跃分数怎么算**（基准：一次按键 = 1 分）：

| 操作 | 得分 |
|---|---|
| 键盘按键 / 鼠标点击 | 1 次 = 1 分 |
| 滚轮 | 10 格 = 1 分（一格 0.1） |
| 摇杆 | 满推往返 **2 次** = 1 分 |
| 扳机 | 满按到底 1 次 = 1 分 |

> 摇杆与滚轮的权重刻意压低：它们阻尼低、几乎不费劲，若按物理行程给权重，长时间推杆会刷出
> 几万分把按键分彻底淹没。摇杆只在**推动过程中**累计（静止按住不加分）。

### 键盘热力图

104 键 ANSI 布局，每个键帽按使用频次着色：灰色 = 未使用，颜色越暖 = 使用越频繁。键帽上直接显示次数。

- **鼠标悬浮任意键帽**：显示键名与精确次数。
- **物理按下键盘按键**：对应键帽会实时亮起并保持按下样式，松开恢复。
- **反转颜色**（图例右侧按钮）：高频键显示色阶低端的颜色、低频键显示高端的颜色；未按键仍为灰色。适合喜欢"冷色 = 用得多"的观察方式。
- **调整大小**：键盘右下角的把手可拖动，无极缩放；也可以拖动键盘与右侧列表之间的分隔条调整两者宽度。

### 鼠标热力图

键盘右侧的鼠标图形：左/右/中键、侧键 X1/X2、滚轮上滑/下滑分别着色计数，同样支持悬浮查看与按下实时反馈。

### 手柄面板

鼠标右侧是一个 Xbox 手柄示意（机身轮廓 + 握把 + 肩键 + 十字键 + 双摇杆 + ABXY + View/Menu），
按 Xbox 布局摆放全部可记录的按键。与键盘鼠标一样**按频次着色**、**物理按下时实时亮起**、
悬浮可看键名与精确次数。

**摇杆怎么看**：每个摇杆画成两个同心圆——**大圈 = 内圈的可移动范围**，**内圈 = 摇杆当前位置**。
向前推杆，内圈就在大圈内向前移动，松手回到中心（已扣除 XInput 官方死区，静止时不会抖动）。
摇杆**按下去**（L3 / R3）算一次按键，会像其它键一样被统计着色。

**扳机怎么看**：面板左右两侧各有一条竖直行程柱，实时显示 **LT / RT 的按下量**——按多深，
柱子就涨多高；完全松开时是空的。线性扳机的中间行程也能看出来。

> 摇杆与扳机的**实时位置**只用于面板显示；但你**推动它们走过的行程会被累计记录**（见
> "手柄行程怎么记"），并计入活跃分数。多手柄同时连接时，实时显示与行程累计都以**第一个
> 已连接的手柄**为准。

#### 手柄行程怎么记

摇杆走了多远、扳机按到多深，程序会**累计**下来（"里程表"模型）：

- **算路程，不算位置**。每个采样周期取一次当前值，算出这一步移动了多远并累加。所以
  **推出去再拉回来算两倍行程**（不会互相抵消成 0），**绕圈推杆也照实累计**。
- **静止不漂移**。手柄放着不动时模拟量会有微小抖动，小于门限的一小步不计入；同时门限加在
  "这一步走了多远"上，所以缓慢但真实的推动不会被吃掉。
- **拔插不虚增**。手柄掉线时会清掉基准，重新插上不会凭空算出一大段假行程。
- **看板怎么显示**：摇杆以"满推往返次数"、扳机以"满按次数"呈现（默认单位）。

**采样率与显示单位**（设置页可调）：

| 设置 | 选项 | 说明 |
|---|---|---|
| 手柄采样率 | 低 30Hz / 中 62Hz / 高 125Hz | 只影响行程累计的精度。XInput 本身约 125Hz，再快无收益；**按键不受影响**（按键是边沿触发，三档一样准） |
| 行程显示单位 | 等效次数 / 毫米 | 等效次数好理解；毫米更有物理实感（摇杆满推往返 ≈ 60mm、扳机满按 ≈ 10mm） |

- **支持范围**：XInput 设备——Xbox 360 / Xbox One / Series 手柄，以及第三方手柄的 **XInput 模式**
  （最多同时 4 个）。走 DirectInput 模式的手柄请在手柄厂商工具或 Steam 里切换为 XInput。
- **按次数统计的**：ABXY / 肩键 / 十字键 / View·Menu / 摇杆**按下**（L3/R3）——这些是数字量，
  进"按键计数"列表；摇杆**推动**与扳机**行程**是模拟量，走行程累计（见上），不出现在按键列表里。
- **无法记录**：手柄中间的 **Xbox（Guide）键**由系统独占上报，XInput 接口不提供给应用程序——
  任何基于 XInput 的软件都拿不到它。
- **没接手柄时**：面板保持灰色，不会报错；插上手柄后按下即有反应（无需重启程序）。

### 着色如何归一化（分组峰值）

峰值不是一个全局数字，而是**键盘组 / 鼠标点击组（左右中侧键）/ 滚轮组（上下左右）/ 手柄组**
各算一份，着色用哪一份**跟着按键筛选走**：

| 筛选 | 键盘键 | 鼠标点击 | 滚轮 | 手柄 |
|---|---|---|---|---|
| 键盘 | 按键盘组峰值 | 保持灰色 | 保持灰色 | 保持灰色 |
| 鼠标 | 保持灰色 | 按点击组峰值 | 按滚轮组峰值 | 保持灰色 |
| 手柄 | 保持灰色 | 保持灰色 | 保持灰色 | 按手柄组峰值 |
| 全部 | 四组共用全局峰值（跨组对比） | 同左 | 同左 | 同左 |
| 分开 | 按键盘组峰值 | 按点击组峰值 | 按滚轮组峰值 | 按手柄组峰值 |

这样设计的原因：滚轮格数通常远大于鼠标点击次数（动辄上万 vs 几十），而键盘次数又远大于手柄
（十几个键 vs 上百个键），共用一个峰值会把小群组压成一片看不出层次的冷色。分组归一化后，
每组内部都能把对比度拉满。未按键始终是灰色；
**反转颜色**与自定义热力色的**平方根分档**都在归一化之后生效，因此可以照常叠加使用。

> 三个面板是各自独立的盒子（键盘 / 鼠标 / 手柄），拖动各自右下角的尺寸指示器可单独缩放；
> 窗口放不下时会自动叠放（键盘在上，鼠标与手柄并排在下），并出现滚动条。

### 按键计数列表（右侧）

所有有记录的按键按次数降序排列（含鼠标、滚轮与手柄），可按「键盘 / 鼠标 / 手柄 / 全部 / 分开」筛选。
**这个筛选同时决定热力图怎么着色**（见上一节）——一处切换，列表与热力图一起变。
「分开」模式下列表会按键盘 / 鼠标 / 滚轮 / 手柄分成四段，段内各自降序；条目的进度条也按同一套
归一化取值，所以各段都会出现满格项。点「收起」可隐藏列表，给键盘区更多空间。

**时间段筛选**（顶部）：`今天 / 7 天 / 30 天 / 全部`，或选自定义日期段后点「应用」。键盘方向键 `←` `→` 也可以翻页/切换。

## 实时按键反馈

主窗口打开时，物理键盘与鼠标的每次按下都会在图形上实时显示：

- 按下即触发键帽按下动画（亮起 + 主题色描边）；
- **按住不放**会持续保持按下样式，但**只计数一次**（不会因系统按键重复而暴涨）；
- 高速连点每次都单独计数。

## 直方图页

第二页显示按键总数随时间的变化，按时段自动聚合：

- 今天 → 每小时一根柱
- 7 / 30 天 → 每天
- 全部 / 长时段 → 每月

鼠标悬浮柱子可看具体数值。

## 主题页：配色与热力方案

第三、四个页签：

- **配色方案**：10 套内置界面配色（深色 / 浅色 / 莫兰迪 / 赛博朋克 / 复古终端 / 森林 / 樱花 / 深海 / 日落 / 北欧极简），点击立即生效并记住。
- **热力渐变**：6 套热力色阶（经典 蓝→黄→红、岩浆、冰川、霓虹、灰度、光谱），与配色方案互相独立、自由组合。
- **自定义主题色**：选一个主色，程序用 HSL 算法推导整套界面配色（背景/面板/文字/强调色），可切深色底或浅色底。
- **自定义热力主色**：取色器（色相条 + 饱和度 + 明度，均支持拖动）选一个主色，生成"同色相、由浅到深"的色阶，并自动启用**平方根分档**——低频段的层次更容易看出来。

## 设置页

- **管理员模式**：开启后程序以管理员权限运行，在管理员权限的游戏窗口内也能记录（重启程序生效）。
- **界面字体**：自动（跟随窗口宽度）或手动滑块调节。
- **手柄采样率**：摇杆/扳机行程的记录精度，三档——低 30Hz / 中 62Hz（默认）/ 高 125Hz。
  **只影响模拟量行程**，按键不受影响。快速搓杆建议调高，见"手柄行程怎么记"。
- **行程显示单位**：手柄行程的呈现方式——**等效次数**（满推往返 / 满按次数）或**毫米**
  （摇杆满推往返 ≈ 60mm、扳机满按 ≈ 10mm）。下方一行给出折算基准与活跃分数口径。
- **开机自启动**：创建**计划任务**（登录触发 + 最高权限），开机由系统服务静默启动后台记录进程 + 托盘（不弹 UAC、游戏内可记录）。普通权限下开启会自动提权重启一次完成创建；关闭开关 = 删除任务。
- **数据文件夹 / 数据文件**：
  - 「更改数据文件夹」可把记录搬到任意位置（切换前会做写入权限预检）；
  - 「新建数据文件」创建带时间戳的新文件并切换（适合分段存档）；
  - 「转入数据文件」把外部的 jsonl 文件移入数据文件夹并启用
    （`analog-*.jsonl` 行程文件会被拒绝——它不是事件文件）。
- **说明文档**：打开本页。

## 托盘与后台记录

程序是**单 exe 双模式**：

| 模式 | 内存 | 职责 |
|---|---|---|
| 后台记录进程 | 约 2 MB | 全局钩子 + 每 5 秒落盘 + 托盘图标 |
| 图形界面 | 约 150 MB | 只读数据文件展示统计 |

- 启动 GUI 时会自动确保后台记录进程在跑；**关闭主窗口后台记录继续**。
- 托盘图标：**双击**或右键「打开 KeyboardStats」唤起主窗口；「退出（停止记录）」优雅收尾（先落盘再退出）。
- 点主窗口 `×` 的行为可配置：**每次询问 / 直接关闭窗口（后台继续记录）/ 退出程序（连后台一起退出）**，可勾选"不再提示"。
- 清除记录、切换数据位置等操作会自动通知后台进程同步。

## 数据存储与管理

- **设置目录**：`%APPDATA%\KeyboardStats`，偏好文件（主题、布局等）固定在这里。
- **数据文件夹**：默认 `<exe 目录>\keyboardstats`，可在设置页更改。
- **数据文件**：自动模式按月一个 `events-YYYYMM.jsonl`；也可显式指定单个文件。第一行是格式标记行，之后每行一个事件：

  ```json
  {"k":65,"t":"2026-09-11T10:30:00.123"}
  ```

  `k` 是 Windows 虚拟键码（鼠标左右键/中键/侧键为 1/2/4/5/6，滚轮上/下/左/右为 224~227，
手柄按键为 256 起的独立段：A 256、B 257、X 258、Y 259、LB 260、RB 261、View 262、Menu 263、
左摇杆按下 264、右摇杆按下 265、十字键上/下/左/右 266~269）。
- **手柄行程文件**：`analog-YYYYMM.jsonl`，按月一个，**每行 = 一小时的累计量**：

  ```json
  {"d":"2026-09-17","h":14,"sl":1.23,"sr":0.87,"lt":2.5,"rt":1.8}
  ```

  `d`/`h` = 日期与小时（本地时间），`sl`/`sr` = 左右摇杆路程，`lt`/`rt` = 左右扳机行程，
  单位都是"等效满推往返次数 / 满按次数"。同一个 (日,时) 可能跨多次写入，**读取时同键相加**。
  它与事件文件分开存放，也**不会被列入"数据文件"**（避免被误当事件文件导入导出）。
- **导出**：设置页可导出 JSONL（原样事件）或 CSV（时间,键码,名称）。
- **清除全部记录**：清空当前数据与内存统计（含手柄行程，会同步重置后台进程）。

## 常见问题

**Q：关掉窗口后还在记录吗？**
在。关窗口只是退出图形界面，后台记录进程继续；点托盘图标随时唤回。只有托盘菜单的「退出」才会停止记录。

**Q：为什么在《无畏契约》（Valorant）等游戏里不记录？**
这类游戏被反作弊（如 Riot Vanguard）强制以高完整性级别运行，而 Windows 的 UIPI 安全机制规定：普通权限进程的输入钩子收不到发往高完整性窗口的键盘/鼠标事件——内核直接跳过，任何普通权限的记录工具都一样，不是程序故障。此时按下动画也不会显示（事件根本没到钩子）。
程序已内置解决方案：在设置页打开**管理员模式**（切换后会自动以管理员权限重启），因此**游戏内也可以正常记录**。开机自启动本身是**最高权限计划任务**，由系统服务静默启动记录进程——不依赖 UAC，也不依赖兼容性标记。

**Q：程序为什么要管理员权限（UAC 弹窗）？**
两个原因：① 管理员（高完整性）钩子可以记录管理员窗口与反作弊游戏（Valorant、原神启动器等）的按键——普通权限会被 Windows UIPI 安全机制屏蔽；② 自启动开关与管理员模式配合使用：开启自启动会创建最高权限计划任务，由系统服务静默提权启动。本程序只被动观察输入，不注入、不修改任何游戏进程。

**Q：按住一个键不放会计多少次？**
只计 1 次。程序会过滤系统的按键自动重复；高速连点则每次都单独计数。手柄按键同理——按住不放只计 1 次。

**Q：手柄为什么有些按键统计不到？**
三种情况：① **Xbox（Guide）键**（手柄中间那个 Logo 键）由系统独占上报，XInput 接口不给应用程序，
任何软件都拿不到；② **摇杆的推动**和 **LT / RT 扳机**是模拟量而不是"按下/松开"——它们不按次数
统计，但**走过的行程会被累计**并计入活跃分数（见"手柄行程怎么记"）；③ **走 DirectInput
模式的手柄**不在 XInput 覆盖范围内——在手柄厂商工具或 Steam 里切成 XInput 模式即可。

**Q：摇杆只是按住不动，活跃分数会一直涨吗？**
不会。行程只在**推动过程中**累计，静止按住时模拟量不变化，一步都不加。

**Q：怎么让手柄行程记录更精确？**
设置页把「手柄采样率」调成"高 · 125Hz"。快速搓杆时低采样率会低估行程（两帧之间的大幅位移
只能算成直线距离）。代价是 CPU 略高一点；XInput 本身约 125Hz，再高已无收益。

**Q：会记录我按了什么内容吗？**
不会。只记录"哪个键、按了几次、什么时间"，无法还原输入内容，数据不出本机。

**Q：后台进程占用多少资源？**
约 2 MB 内存、CPU 接近 0（事件驱动 + 5 秒批量落盘）。

**Q：想彻底删掉数据？**
直接删除数据文件夹（或设置页「清除全部记录」）。卸载程序只需删除 exe 与数据文件夹、关闭自启动即可，无其它残留。
